================================================================================
                     BUMBULL API REFERENCE – FRONTEND EDITION
================================================================================

Base URL: http://your-domain.com
All endpoints are relative to this base.

Authentication: Session-based (Django SessionAuthentication).
- Login: POST /accounts/login/
- Logout: GET /accounts/logout/
- CSRF token: GET /accounts/api/csrf/  (returns {"csrf_token": "..."})
  Include the token in the X-CSRFToken header for POST/PUT/PATCH/DELETE.

================================================================================
ACCOUNTS APP
================================================================================

1. Registration (4‑step flow)
─────────────────────────────
Step 1   POST   /accounts/register/           Submit basic info (first name, last name, DOB, gender, password). Returns OTP.
Step 2   GET    /accounts/register/           Show OTP (user sends it via Telegram; bot redirects back with ?token=...).
Step 3   POST   /accounts/register/           After token verification (user logged in), submit location & bio (step 3 fields).
Step 4   POST   /accounts/register/           Upload 3‑6 photos (multipart/form-data).

2. Authentication
─────────────────
POST   /accounts/login/                       Login with phone_number and password.
GET    /accounts/logout/                      Logout current user.
POST   /accounts/password-reset/request/      Request reset link (sent via Telegram). Body: {"phone_number": "+989..."}.
POST   /accounts/password-reset/confirm/      Confirm reset with token and new_password.

3. Profile & User Management
────────────────────────────
GET    /accounts/profile/<slug>/              Public profile of any user.
GET    /accounts/profile/me/                  Redirect to your own profile.
GET    /accounts/profile/edit/                Edit profile (full form).
GET    /accounts/profile/quick-edit/          Quick edit (name, bio, city).
GET    /accounts/settings/                    Account settings page.
POST   /accounts/settings/delete/             Deactivate account (requires "password").
POST   /accounts/settings/password/           Change password (old, new1, new2).

4. Photo Management
───────────────────
GET    /accounts/photos/manage/               List/order photos.
GET    /accounts/photos/upload/               Upload single photo.
GET    /accounts/photos/upload-multiple/      Upload 1‑5 photos at once.
POST   /accounts/photos/delete/<pk>/          Delete a photo.
POST   /accounts/photos/set-primary/<pk>/     Set as primary photo.
POST   /accounts/photos/reorder/              Reorder photos. Body: {"orders": [{"id": 1, "order": 0}, ...]}

5. Swiping & Matching
─────────────────────
GET    /accounts/swipe/                       HTML view for swiping (shows one profile).
POST   /accounts/swipe/action/                Perform a swipe. Body: {"swiped_user_id": 123, "swipe_type": "like|pass|super"}.
                                              Returns match info.
GET    /accounts/api/swipe/                   JSON endpoint – returns the next profile to swipe.
GET    /accounts/api/matches/                 List your matches (with partner info and last message).

6. User Discovery
─────────────────
GET    /accounts/users/                       Search/filter users (HTML).
GET    /accounts/users/nearby/                Users near you (based on GPS).
GET    /accounts/api/users/                   API user list (paginated). Query params: search, gender, city, membership,
                                              age_min, age_max, page, page_size.
GET    /accounts/interests/                   List all interests.
GET    /accounts/interests/<slug>/            Users with that interest.

7. Dashboard & Stats
────────────────────
GET    /accounts/dashboard/                   HTML dashboard.
GET    /accounts/api/profile-completion/      Returns {"complete": bool, "missing_fields": [...], "completion_percentage": int}
GET    /accounts/api/user-stats/              Global stats (total users, membership counts, etc.).
GET    /accounts/api/profile/me/              Full profile of current user (JSON).
PUT/PATCH /accounts/api/profile/update/       Update profile fields (partial allowed).

================================================================================
CHAT APP
================================================================================

Prefix: /chat/
WebSocket: ws://<domain>/ws/chat/<match_id>/

1. REST API
───────────
GET    /chat/api/matches/                     List all your matches with partner info, last message, unread count.
GET    /chat/api/matches/<match_id>/messages/ Get messages (pagination: ?limit=50&offset=0).
POST   /chat/api/matches/<match_id>/read/     Mark messages as read. Body: {"message_ids": [1,2,3]} (optional).
GET    /chat/api/matches/<match_id>/partner-status/  Check if partner is online and last seen.
DELETE /chat/api/messages/<message_id>/       Soft‑delete your own message.
GET    /chat/api/unread-counts/               Get unread count per match.

2. WebSocket Actions (send JSON)
─────────────────────────────────
Action "chat_message"   {"action": "chat_message", "content": "Hello!"}
Action "typing"         {"action": "typing", "is_typing": true}
Action "mark_read"      {"action": "mark_read", "message_ids": [1,2]}
Action "ping"           {"action": "ping"}  (responds with "pong")

3. Incoming WebSocket Events
─────────────────────────────
event: "message"       – new chat message (data includes sender, content, timestamp)
event: "typing"        – partner typing indicator
event: "status"        – partner online/offline status
event: "read_receipt"  – partner has read messages
event: "error"         – error message

================================================================================
EVENTS APP
================================================================================

Prefix: /events/
WebSocket: ws://<domain>/ws/events/<event_id>/

1. REST API
───────────
GET    /events/api/                          List active events (paginated). Query params: city, from_date, to_date,
                                              upcoming=true/false, order_by, page, page_size.
POST   /events/api/                          Create a new event (admin/staff only).
GET    /events/api/<id>/                     Event detail. Private address shown only if attending/waitlisted.
PATCH  /events/api/<id>/                     Update event (admin only).
DELETE /events/api/<id>/                     Delete event (admin only).
POST   /events/api/<id>/join/                Join an event (or get waitlisted).
POST   /events/api/<id>/leave/               Leave an event (promotes first waitlisted).
GET    /events/api/<id>/messages/            Get last 50 messages (participants only).
POST   /events/api/<id>/messages/            Send a message (participants only). Body: {"content": "..."}.
GET    /events/api/my-events/                Events you are attending or waitlisted for.
GET    /events/api/upcoming/                 List upcoming events (not started).
GET    /events/api/admin/                    Admin list all events (staff only).

2. WebSocket Actions (send JSON)
─────────────────────────────────
Action "chat_message"   {"action": "chat_message", "content": "Hello!"}
Action "typing"         {"action": "typing", "is_typing": true}
Action "ping"           {"action": "ping"}

3. Incoming WebSocket Events
─────────────────────────────
event_chat_message  – new message from a participant.
event_update        – when someone joins/leaves (contains updated participant counts).
error               – error message.

================================================================================
REQUEST / RESPONSE EXAMPLES
================================================================================

Login (POST /accounts/login/)
Request:
  {"username": "+989123456789", "password": "mypassword"}
Response: Redirects to profile on success; errors in form.

Swipe action (POST /accounts/swipe/action/)
Request:
  {"swiped_user_id": 42, "swipe_type": "like"}
Response:
  {"success": true, "match": {"id": 101, "created_at": "2026-06-28T12:34:56Z"},
   "match_created": true, "match_blocked": false}

Get messages (GET /chat/api/matches/1/messages/?limit=20&offset=0)
Response:
  [{"id": 1001, "sender": {"id": 2, "first_name": "Jane", "last_name": "Doe"},
    "content": "Hey!", "timestamp": "2026-06-28T10:00:00Z",
    "is_read_by_me": true, "read_by_other": false}]

Join event (POST /events/api/5/join/)
Response:
  {"message": "Successfully joined the event.", "status": "attending"}

================================================================================
TESTING WITH INSOMNIA / POSTMAN
================================================================================

- Authentication: Use session cookies. First login via /accounts/login/.
- CSRF: For state‑changing requests, include X-CSRFToken header with token from /accounts/api/csrf/.
- File uploads: Use multipart/form-data.

================================================================================
FRONTEND TIPS
================================================================================

- Realtime updates: Subscribe to WebSocket rooms after joining a match or event.
- Unread counts: Poll /chat/api/unread-counts/ or update via WebSocket.
- Profile completion: Use /accounts/api/profile-completion/ to show progress bars.
